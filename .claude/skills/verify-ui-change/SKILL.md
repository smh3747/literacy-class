# UI 변경 자체 검증

빌드 통과만으로 UI 변경을 완료로 보고하지 않는다. 커밋 전에 아래를 수행:

1. npm run build 통과 확인.
2. 변경된 화면의 렌더 경로를 코드로 재확인:
   - 이번에 수정/추가한 요소가 실제 JSX 렌더 트리에 존재하는가
   - 기존 요소(버튼·배지·핸들러)가 실수로 제거되지 않았는가 — 변경 전후 diff에서 삭제된 줄을 전수 훑고, 삭제가 의도된 것인지 명시적으로 판정
3. 조건부 렌더( {cond && ...} )를 새로 만들거나 수정했다면, 각 조건 분기에서 무엇이 보이고 무엇이 숨는지 보고에 명시 (예: "unread=0이면 버튼 숨음").
4. 공용 컴포넌트(components/) 수정 시: 그 컴포넌트를 쓰는 페이지를 grep으로 전수 확인하고 영향 범위를 보고에 적는다.
5. 브라우저 실확인이 필요한 항목(색·간격·실데이터)은 "사용자 확인 필요"로 구분해 기대값(문구·색·위치)을 명시한다.

어느 단계든 실패하면 고치고 1부터 다시. 부분 검증 상태로 완료 보고 금지.
